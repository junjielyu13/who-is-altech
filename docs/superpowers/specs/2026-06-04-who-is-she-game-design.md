# "Who Is She" 猜照片游戏 — 设计文档

日期：2026-06-04
状态：已确认，待写实现计划

## 1. 概述

一个 Kahoot 风格的线下聚会游戏。一块大屏（投影）把照片**按格子一块一块自动露出**，参与者用手机扫码加入，**手动输入名字**猜照片里是谁。**露出的格子越少就猜中，得分越高**。游戏强调"同一个房间一起看大屏"的聚会气氛。

### 玩法要点（已与用户确认）

- 场景：线下聚会，**同屏**（一块大屏 + 每人手机加入）
- 答题方式：**手动输入名字**，带容错匹配
- 计分：**越早猜中（露出格子越少）得分越高**
- 露图：**自动定时**逐块露出；本轮在「有人猜中」或「全部露完」或「主持人手动跳过」时结束
- 准备：主持人**提前上传**一组照片并配置答案，存成题库
- 范围：一次一局（单个活动游戏），不做多房间（YAGNI）

## 2. 技术栈与架构

方案 A：一个轻量 Node 服务器。

```
┌─────────────────────────────────────────────┐
│  Node.js 服务器 (Express + Socket.IO)          │
│  - 提供 3 个页面 + 静态资源/照片                  │
│  - 内存里保存当前游戏状态 (GameState)             │
│  - 通过 WebSocket 实时广播给所有客户端            │
└─────────────────────────────────────────────┘
        │ HTTP            │ WebSocket
   ┌────┴─────┐    ┌──────┴───────┬──────────────┐
   │ 配置页    │    │ 主持人大屏页   │  玩家手机页(N个) │
   │ /admin   │    │ /host        │  /play        │
   └──────────┘    └──────────────┘ └─────────────┘
```

- **后端**：Node.js + Express（HTTP / 静态文件）+ Socket.IO（实时通信）。
- **状态**：游戏状态保存在服务器内存中，单个活动游戏即可。
- **前端**：纯 HTML/CSS/原生 JS，每个页面一套，不引重型框架。
- **照片网格**：用 CSS grid 在照片上叠一层遮罩块，逐块移除遮罩实现"露出"。
- **存储**：照片上传到服务器本地 `uploads/` 目录；题库配置存为 `quiz.json`。

### 目录结构（建议）

```
/server
  index.js          # Express + Socket.IO 启动
  game.js           # GameState 状态机（纯逻辑，可测）
  scoring.js        # 计分公式（纯函数，可测）
  matching.js       # 答案归一化与匹配（纯函数，可测）
  quizStore.js      # 读写 quiz.json、处理上传
/public
  admin.html / admin.js / admin.css
  host.html  / host.js  / host.css
  play.html  / play.js  / play.css
  shared.css
/uploads            # 上传的照片（运行时生成）
quiz.json           # 题库配置（运行时生成）
/test               # 单元 + 集成测试
```

## 3. 三个页面的职责

### `/admin` 配置页（玩前准备）

- 上传多张照片，每张填：**正确答案** + 可选**别名列表**（逗号分隔）
- 每张照片可设：网格大小（默认 4×4，可选 5×5 等）、每块露出间隔（默认 3 秒）
- 保存为题库 `quiz.json`
- 校验：非图片文件或缺少正确答案时报错

### `/host` 主持人大屏页（投影用）

- 顶部：**二维码** + 加入网址（手机扫码进 `/play`）
- 等待区：显示已加入玩家的昵称列表
- 主持人点「开始」→ 进入答题：大图按格子逐块露出，显示倒计时与「已答人数」
- 本轮结束：揭晓答案 + 本轮得分动画
- 每轮之间显示排行榜；最后显示总冠军
- 主持人可「手动跳过」当前轮

### `/play` 玩家手机页

- 输入昵称加入
- 每轮：一个文本框，输入猜测名字并提交。**玩家手机不显示照片**——照片只在大屏，保证大家一起看大屏的聚会气氛
- 提交后显示「已锁定，等待揭晓」；揭晓时给猜中/猜错反馈与得分
- 断线重连后恢复昵称与本轮状态

## 4. 游戏循环与状态机

状态：`LOBBY`（等待加入）→ `REVEALING`（逐块露图、收答案）→ `ROUND_RESULT`（本轮结算）→ 回到 `REVEALING`（下一张）或 `GAME_OVER`（全部结束）。

一轮流程：

1. 主持人开始本轮，服务器记录开始、当前露出块数 `r = 0`
2. 服务器每隔 N 秒广播「露出第 k 块」，`r` 递增
3. 玩家随时提交猜测（每轮只能提交一次，提交即锁定其猜中时刻 `r`）
4. 本轮结束条件（任一满足）：
   - 全部 `T` 块露完
   - 主持人手动跳过
   - （注：因为允许多人答对，不在"第一个人猜中"时立即结束，让更多人有机会；是否提前结束可由主持人手动跳过控制）
5. 进入 `ROUND_RESULT`：揭晓答案、为每个答对的玩家按其锁定时刻计分、更新排行榜
6. 下一张或结束

## 5. 计分公式

一张照片共 `T` 块，玩家在已露出 `r` 块时**提交且答对**：

```
得分 = ceil( 1000 × (T - r) / T )
若结果为 0（最后一块才中），给保底分 50
猜错或未提交 → 0 分
```

- 所有答对的玩家都按各自锁定时刻得分（不只第一名），更适合聚会
- 每位玩家**每轮只能提交一次**，提交即锁定 `r`，防止狂试

示例（T=16）：r=1 → 938；r=8 → 500；r=16 → 50（保底）。

## 6. 答案匹配（手动输入容错）

对玩家输入与该题的「正确答案 + 所有别名」分别归一化后比较：

1. 转小写
2. 去掉首尾及多余空格（多个空格合并为一个）
3. 去掉标点符号
4. 完全相等 → 正确
5. 容错：允许 ≤1 个字符的编辑距离（防手滑打错一个字母）

## 7. 错误处理

- 玩家手机断线重连：用客户端保存的会话标识恢复昵称与本轮提交状态
- 主持人断线：游戏状态在服务器内存中不丢，重连后继续
- 配置上传：非图片文件或缺答案时报错，不写入题库
- 题库为空时主持人页禁止「开始」

## 8. 测试策略

采用测试驱动开发（先测后写）。

- **单元测试（重点）**：
  - `scoring.js` 计分公式（含保底分、边界 r=0/T）
  - `matching.js` 归一化与匹配（大小写、空格、标点、别名、1 字符容错）
  - `game.js` 状态机（开始 / 露块 / 结算 / 换轮 / 跳过）
- **集成测试**：Socket.IO 事件——玩家加入、提交、断线重连、广播露块
- **手动联调**：本地起服务，手机 + 电脑实际扫码玩一局

## 9. 明确不做（YAGNI）

- 多房间 / 房间码（一次一局）
- 用户账号 / 持久化数据库（内存 + 文件即可）
- 玩家手机端显示照片（只在大屏）
- 公网部署（先本地局域网；架构不阻碍将来部署）
